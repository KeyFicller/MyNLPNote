## 课程概述

第32课介绍了字典格式的 `messages` 列表与 `invoke` 单次调用；本课在此基础上实现**可交互的多轮对话**：用户在终端输入，模型流式回复，并通过滑动窗口控制每次 API 请求携带的历史长度。

示例设定「杠精」人设，便于在多轮中观察模型是否记住上下文、是否延续对话风格。

**学习目标：**
1. 理解 OpenAI 风格 `messages` 列表在多轮对话中的累积方式
2. 掌握 `stream` 在聊天循环中的用法与回复拼接
3. 实现「全量本地历史 + 截断后发送」的双层记忆策略
4. 了解上下文窗口限制及常见截断方案

## 1. 为什么需要消息历史？

### 1.1 单轮 vs 多轮

```python
# 单轮 — 模型不知道上一轮说了什么
llm.invoke("我叫小明")
llm.invoke("我叫什么？")  # 回答：我不知道
```

LLM 本身**无状态**：每次 API 调用独立，模型不会自动记住上次内容。多轮对话必须在每次请求中**显式传入完整上下文**。

### 1.2 messages 列表即「短期记忆」

```
第1轮  [system] [user₁]                    → assistant₁
第2轮  [system] [user₁] [assistant₁] [user₂] → assistant₂
第3轮  [system] ... [user₃]                → assistant₃
              ↑
        每次 invoke/stream 都要带上
```

这与第24课 Agent 中的 `messages.append(...)`、第27课 Gradio 的 `history` 本质相同：**用结构化列表承载对话状态**。

## 3. 核心流程

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────┐
│                    main 循环                         │
├─────────────────────────────────────────────────────┤
│  messages（本地全量历史，只增不减）                    │
│       ↓                                              │
│  _maintain_messages() 截断                           │
│       ↓                                              │
│  memory_messages（实际发给 API 的子集）                │
│       ↓                                              │
│  llm.stream(memory_messages)  →  逐块打印 + 拼接      │
│       ↓                                              │
│  messages.append(assistant 回复)  进入下一轮          │
└─────────────────────────────────────────────────────┘
```

**关键设计**：本地保存完整历史（便于调试或持久化），请求时只发送最近若干条，平衡**上下文连贯性**与 **Token 成本 / 窗口上限**。

### 3.2 初始化 system 消息

```python
messages = [
    {
        "role": "system",
        "content": "你是一个杠精，喜欢和用户抬杠。"
    }
]
```

`system` 消息定义人设与行为边界，通常**始终保留**，不参与截断。示例用「杠精」人设，方便测试多轮风格是否一致。

### 3.3 主循环 — 读入、截断、流式、写回

```python
while True:
    user_input = input("请输入：")
    if user_input.lower() == EXIT_WORD:
        break

    messages.append({"role": "user", "content": user_input})

    memory_messages = _maintain_messages(messages, memory_round=3)
    reply_content = ""

    for chunk in _chat_deepseek().stream(memory_messages):
        if chunk.content:
            print(chunk.content, end="", flush=True)
            reply_content += chunk.content

    messages.append({"role": "assistant", "content": reply_content})
```

| 步骤 | 说明 |
|------|------|
| `append user` | 先把用户输入记入全量历史 |
| `_maintain_messages` | 从全量历史中取出要发给 API 的子集 |
| `stream` | 流式输出，`chunk.content` 可能为空需过滤 |
| 拼接 `reply_content` | 流式片段需手动拼成完整回复再存回 `messages` |

注释中还保留了 `invoke` 写法作为对照：非流式时一次拿到 `response.content`，逻辑更简单，但无「打字机」效果。

## 4. 历史截断 — `_maintain_messages`

```python
def _maintain_messages(messages: list[dict], memory_round=2) -> list[dict]:
    system_messages = [msg for msg in messages if msg["role"] == "system"]
    conversation_messages = [
        msg for msg in messages if msg["role"] in ["user", "assistant"]
    ]
    return system_messages + conversation_messages[-memory_round:]
```

### 4.1 逻辑拆解

1. **分离 system**：所有 `role == "system"` 的消息完整保留（通常只有一条）
2. **提取对话**：只取 `user` / `assistant` 消息
3. **滑动窗口**：`[-memory_round:]` 保留对话列表的**最后 N 条消息**

```
全量 messages:
  [system] [u1] [a1] [u2] [a2] [u3]     memory_round=3
                ↓
发送给 API:
  [system] [a2] [u2] [u3]   ← 最近 3 条 user/assistant（示例）
```

### 4.2 参数含义：条数 vs 轮数

⚠️ **注意**：`memory_round` 在代码中表示「保留最后几条 user/assistant **消息**」，不是「几轮对话」。

| 概念 | 1 轮对话通常包含 |
|------|------------------|
| 1 轮 | 1 条 `user` + 1 条 `assistant` = **2 条消息** |
| 保留 3 轮 | 应保留约 **6 条** user/assistant 消息 |

示例中 `memory_round=3` 实际只保留约 1～2 轮上下文（取决于当前轮是否已写入 assistant）。若需「最近 3 轮」，应改为 `memory_round=6` 或按轮数重写截断逻辑：

```python
def _maintain_messages_by_turns(messages: list[dict], max_turns: int = 3) -> list[dict]:
    system_messages = [m for m in messages if m["role"] == "system"]
    conv = [m for m in messages if m["role"] in ("user", "assistant")]
    # 每轮 2 条消息 → 保留最后 max_turns * 2 条
    return system_messages + conv[-(max_turns * 2):]
```

### 4.3 为何 system 不参与截断

System 指令定义模型行为；若被截掉，人设会「漂移」。生产环境常见策略：

| 策略 | 做法 |
|------|------|
| **滑动窗口** | 本示例：保留 system + 最近 N 条对话 |
| **摘要压缩** | 旧对话用 LLM 总结成一条 system 补充 |
| **向量检索** | 从长期库检索相关历史片段注入 prompt |
| **LangChain Memory** | `ConversationBufferWindowMemory` 等封装 |

第19课介绍的 `ConversationBufferWindowMemory` 与本示例手写截断思路一致，本课更贴近**裸 API 层**的实现，便于理解 Memory 类底层在做什么。

## 5. 流式 vs 非流式

### 5.1 流式（本示例采用）

```python
for chunk in llm.stream(memory_messages):
    if chunk.content:
        print(chunk.content, end="", flush=True)
        reply_content += chunk.content
```

- **优点**：首 token 延迟低，终端体验接近 ChatGPT
- **注意**：必须自己拼接 `reply_content`，否则无法写回 `messages`
- **空 chunk**：部分 chunk 仅含元数据，`if chunk.content` 不可省略

### 5.2 非流式（注释中的备选）

```python
response = llm.invoke(memory_messages)
messages.append({"role": "assistant", "content": response.content})
```

- **优点**：代码更短，直接拿完整 `AIMessage`
- **缺点**：需等整段生成完毕才显示

第27课 Gradio 聊天界面底层也常用 `stream`，与本示例终端打字机效果同源。

## 6. 消息格式速查

与 OpenAI Chat Completions 一致，LangChain `ChatDeepSeek` 均支持：

| role | 含义 | 本示例 |
|------|------|--------|
| `system` | 系统指令 | 杠精人设 |
| `user` | 用户输入 | 终端 `input()` |
| `assistant` | 模型历史回复 | 流式拼接后的 `reply_content` |

```python
{"role": "user", "content": "今天天气真好"}
{"role": "assistant", "content": "好什么好，又要上班了不是吗？"}
```

第32课还介绍了 `SystemMessage` / `HumanMessage` / `AIMessage` 对象形式；字典与本示例等价，Chain 内部会统一转换。

## 8. 常见问题

### Q1: 模型「忘记」早期对话内容？

这是预期行为：`_maintain_messages` 故意不发送过早的消息。增大 `memory_round` 或改用按轮截断；若仍不够，考虑摘要或 RAG 式历史检索。

### Q2: 每轮都 `_chat_deepseek()` 新建实例，有影响吗？

示例为简洁每次调用工厂函数。生产环境可在循环外创建一次 `llm = _chat_deepseek()` 复用连接。功能上无本质区别。

### Q3: 全量 `messages` 会一直变大吗？

会。本示例仅演示请求截断，**未**持久化到磁盘。长时间运行可定期清理本地列表，或只持久化摘要。

### Q4: 能否在 stream 时用 LangSmith 追踪？

可以。为 `stream` 传入与第33课相同的 `config`（`run_name`、`tags`），并在环境变量中开启 `LANGSMITH_TRACING=true`。

### Q5: user 和 assistant 必须严格交替吗？

OpenAI 兼容 API 一般期望合理交替；连续多条 `user` 通常仍可工作，但可能影响模型理解。本示例每轮先 user 再 assistant，结构规范。

## 9. 动手练习

1. **感受上下文窗口**：连续聊 5 轮后问「我第一轮说了什么？」观察 `memory_round=3` 时模型是否答不上来
2. **改保留策略**：实现 `_maintain_messages_by_turns`，保留最近 3 **轮**（6 条消息），对比效果
3. **切换 invoke**：取消注释 `invoke` 分支，注释 `stream`，对比代码与体验差异
4. **改人设**：修改 system 内容为「耐心助教」，验证截断后 system 是否仍生效
5. **加 LangSmith**：结合第33课，为每轮 stream 设置 `run_name=f"round-{i}"`，在控制台查看多轮 Trace
